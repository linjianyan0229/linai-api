# 邀请返利现金提现

- 金额沿用 USD 返利账本，最多 8 位小数；管理员线下打款，系统不自动转账。
- 每笔返利从原始入账时间开始计时，滚动 24 小时内可申请，恰好 24 小时时已过期。
- 超期只影响现金申请资格；返利仍按原冻结规则转入站内余额。
- 已在期限内提交的申请保持有效，等待处理不会导致申请过期。
- 冻结中的返利允许先申请，系统占用对应额度；冻结期结束前不能登记已打款。

## 使用

用户在“邀请返利 → 返利现金提现”填写收信邮箱、USD 金额并上传收款码。
收款码仅接受完整 PNG/JPEG/WebP 图片，最大 2 MiB、单边最大 4096 像素。
提交后可在下方查看申请记录、处理状态和管理员回复。

管理员在“订单管理 → 提现申请”打开详情，查看邮箱、金额、收款码和回复记录。
可以仅回复、登记已线下打款，或驳回并退回返利。完成线下打款后才应登记已打款。
驳回会归还原返利份额，不修改原到账时间或续期；已过期部分不能再次申请现金提现。

“保存处理并发送回复”先保存处理结果和回复，再调用系统现有 SMTP 配置发信。
邮件发送失败不会撤销处理或再次扣款；管理员可以针对同一条已保存回复重试发送。
发送中断且超过 5 分钟仍未确认结果时显示“发送结果待确认”，重发前需核对发信记录并明确确认可能重复发信。
不自动重试不确定投递，以免重复邮件。SMTP 本身无法保证收件人只收到一次。

## 存储与一致性

迁移 `250_affiliate_cash_withdrawals.sql` 为返利入账记录增加未使用份额，
并创建申请、原始份额占用和回复表。旧数据按现有可用/冻结池分别回填，优先保留较新的未使用返利。
缺少原始入账记录的旧额度仍可按原规则转余额，不凭空赋予现金申请资格。

申请、解冻、转余额、原有管理员线下提现和申请处理共用每用户返利档案锁。
申请及归还按 NUMERIC 计算；重复申请和处理使用幂等键。
已打款时只记录一次出账，不再次扣减已占用份额。
收款码存于数据库，通过本人或完整管理员权限的认证接口读取，响应禁止缓存。
受限管理员 API 密钥不会继承这些接口的权限。审计记录访问和处理动作，不保存收款图片或回复正文。

升级时应确保所有实例运行支持本迁移的代码，避免旧实例写入不跟踪份额的返利流水。
