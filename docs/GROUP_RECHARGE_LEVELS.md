# 分组累计充值等级倍率

从 v0.3.60 起，管理员可在「分组管理 → 创建 / 编辑标准余额分组 → 累计充值等级倍率」启用三级配置。已有分组默认关闭，保留原有计费。

## 配置与优先级

开启时提供三个可调整的档位，默认示例为：

| 等级 | 累计本金门槛（USD） | 分组倍率 |
| --- | ---: | ---: |
| 1 | 0 | 1 |
| 2 | 100 | 0.75 |
| 3 | 500 | 0.5 |

首档门槛固定为 0，其他门槛严格递增，最多两位小数。倍率在 0.5–1 之间，严格递减，最多四位小数。每个分组单独设置；复制分组会复制档位。

生效顺序为：管理员为该用户手工设置的专属倍率 → 达到的最高充值档位倍率 → 分组默认倍率。档位倍率直接替代默认倍率，不额外相乘。原有高峰计费及独立图片 / 视频定价继续遵循各自规则。订阅分组不使用充值档位。

## 本金与退款

本金读取用户历史已成功到账的余额充值订单：`amount - bonus_amount`。支付网关金额可能采用人民币等币种并包含手续费，因此不直接使用 `pay_amount`。赠金、兑换码、返利转余额、管理员调整余额和订阅付款不累计。账户消费不降低等级。

申请退款、处理中和失败的退款不扣本金；成功部分 / 全部退款按 `refund_amount / amount` 比例扣回对应订单的本金，每单保留两位小数。查询订单快照而非在支付回调中累加，因此重复回调不会重复提升等级。

网关沿用用户分组倍率缓存，最长 30 秒。充值到账、退款成功和修改档位后，计费倍率在 30 秒内更新；用户充值页重新打开时读取当前本金和进度。尚未达到任何付费门槛的用户使用第一档。

## 展示与数据

用户充值页显示有权使用且启用本功能的分组、当前档位、实际倍率和距离下一档所需本金。存在手工专属倍率时明确提示优先使用专属倍率。模型广场和用户分组倍率接口也返回派生倍率；管理员编辑专属倍率的接口仍仅返回手工设置，避免意外将动态档位固定为专属倍率。

- 数据迁移：`252_group_recharge_rate_tiers.sql`，新增 `groups.recharge_rate_tiers`，空数组表示关闭。
- 用户接口：`GET /api/v1/groups/recharge-progress`，需登录，按当前用户的分组权限过滤。
- 无新增真实支付操作，也不修改已有订单金额或账户余额。

验证覆盖门槛边界、配置校验、克隆隔离、权限过滤、赠金排除、重复支付通知、退款各状态、专属倍率优先、数据库读写以及实际网关共享倍率路径。
