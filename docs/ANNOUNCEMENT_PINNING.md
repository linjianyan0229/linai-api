# 公告置顶

在管理后台的“公告管理”中，点击某条公告的“置顶”或“取消置顶”。可同时置顶多条公告。置顶状态持久保存在数据库，升级迁移 `255_announcement_pinning.sql` 后，现有公告默认不置顶。

后台列表在分页前优先排列置顶公告，再按用户选择的列排序。用户公告在查询上限及前端 20 条展示上限前应用置顶优先级；同一优先级内保留未读优先、ID 倒序。顶部轮播仍每 5 秒轮换，置顶公告优先展示，并显示“置顶”标记。公告列表、详情及弹窗也显示该标记。

置顶操作立即刷新当前页面的管理列表和共享公告数据。已登录、可见的其他页面每 30 秒自动检查公告更新，切回页面时也会检查；后台标签暂停轮询，退出登录或页面卸载后清理轮询。轮播在公告顺序或置顶状态改变时回到第一条。

置顶不发布草稿，不延长有效期，不绕过余额或订阅等投放条件，也不清空已读记录。更新仅修改置顶和管理员审计字段；公告邮件的内容修订触发器不将置顶变化视为重新发布，因此不会额外发送邮件。当前会话已展示过的弹窗不会因为置顶重复弹出。并发的内容编辑不会覆盖独立保存的置顶状态。

管理员接口：`PUT /api/v1/admin/announcements/:id/pin`，请求为 `{"is_pinned":true}` 或 `{"is_pinned":false}`，必须显式提供布尔值。接口返回更新后的公告；读取接口新增 `is_pinned` 字段。管理员会话可使用该操作，受限管理密钥需要 `announcements.write` 权限，仅有读取权限不能置顶。
