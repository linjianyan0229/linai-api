# OpenAI 分组上游动态倍率

在「分组管理 → 编辑分组 → 上游动态倍率」开启，设置上游倍率的倍数。

开启条件：分组为 OpenAI，且已绑定至少一个状态正常的 OpenAI API Key 账号；该账号开启上游倍率探测，并已取得成功、未过期的 token 倍率声明。手工填写的账号倍率、OAuth 账号及不支持声明接口的官方上游不能作为动态报价来源。新建、升级及复制出的分组默认关闭此功能。

## 用户计费

最终分组倍率 = 本次选中的上游当前声明倍率 × 动态倍数。

例如上游 0.08×，设置 2 倍，最终为 0.16×；后续探测取得 0.1× 时，新请求使用 0.2×。不同上游分别使用自己的报价，不取组内某个固定账号的价格。声明包含上游分时规则时，使用上游声明的时区重新计算其当前倍率。

充值等级、本站峰谷规则、用户专属倍率在动态模式期间暂停，原配置保留，关闭动态模式后恢复。共享分组倍率的图片、视频、搜索收费使用动态值；独立图片/视频倍率及 Live 等既有独立定价保持原有口径。模型基础单价、服务等级定价仍按各自配置执行，所以倍率的倍数不代表跨站实际总费用的固定利润比例。

账号成本、额度统计及利润保护仍使用管理员配置的账号倍率及其已有自动同步设置。动态开关不隐式启用账号成本同步。需要成本跟随上游时，可在账号设置中启用已有的上游倍率自动同步。

## 报价有效期与请求快照

- 随现有账号探测任务更新，不对每个推理请求增加远程探测。
- 缺少报价、探测关闭、最新探测失败、不支持或报价过期的账号不参与动态组的普通请求调度；关闭利润保护也不会绕过该校验。
- 所有普通 OpenAI 转发路径在付费请求前取得报价。没有报价时返回可重试的 503，允许重选其他有效上游。
- 每次尝试与每个 WebSocket 轮次单独冻结最终倍率和已有账号成本倍率。长请求结束前探测更新或过期不会重算该请求。失败重选时使用实际成功上游的快照。
- 已打开的 WebSocket 在后续轮次刷新分组配置。无法取得有效报价时要求重连重选，不沿用过期价格。
- 本次动态值不写入 user:group 倍率缓存，不修改共享 Account/Group 对象。

允许明确声明的 0× 免费报价；其用户费用为 0，账号成本与利润保护继续遵循账号配置。上游当前有效倍率范围为 0–100，动态倍数为正数、最多四位小数、最大 9999.9999。

## API 与展示

管理员更新接口新增 `dynamic_rate_enabled`、`dynamic_rate_factor`；开启或修改已启用的倍数时后台重新校验报价。

`GET /api/v1/admin/groups/:id/dynamic-rate-availability` 返回可用报价数量及上游倍率区间，仅授予 `groups.read` 权限；不向分组模型查询权限开放。

用户接口仅提供动态状态及计算后的销售倍率参考区间，不提供账号身份、凭据、上游原始数据或动态倍数。模型广场按当前参考区间上限展示估算价格，实际费用以请求所选上游的冻结报价为准。

动态组无法通过 schema-1 协议声明单个固定 token 倍率，因此 `/v1/sub2api/billing` 返回 501。已有探测器将其视为不支持并清除旧的固定报价；不伪造固定倍率供多级代理继续计价。

迁移 `256_group_dynamic_rate.sql` 保存开关及倍数，并为实际配置变化生成认证缓存失效事件。认证快照版本升级为 28；旧分组的计费设置默认不变。
