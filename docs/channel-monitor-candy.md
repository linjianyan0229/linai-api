# 糖果降智监控

在管理端「渠道监控」编辑或新建一个 OpenAI 类型的探活监控，设置上游地址、密钥与主模型，再开启「糖果降智检测」。默认关闭。纯配额监控没有可检测的模型，因此不提供此开关。

开启后立即安排首次检测，之后独立于可用性探活的间隔，每 10 分钟检测一次。用户端渠道状态卡片中的「降智监控」条展示最近 60 次结果；未开启时显示「未启用」。其他类型的监控不会显示此条。

后端调用 [满血AI 糖果接口](https://manxue.ai/api)：以 `benchmark: candy` 提交当前监控的上游地址、密钥和主模型，并轮询该任务。地址路径与现有 OpenAI 探活保持一致。接口使用 Responses API；启用意味着将上述信息交给 manxue.ai，并产生对应上游模型用量。自定义请求体中的有效推理程度与服务档位会沿用；接口不支持透传监控的自定义请求头。

`passed` 显示「正常」，`incorrect` 显示「疑似降智」；网络错误、无法判定、超时和取消显示「检测失败」。通过率排除检测失败，且不会改变可用率、延迟或配额统计。单次糖果结果仅说明本次题目的完成情况。

数据库会原子认领任务，防止多实例或重复调度提交同一个检测；完成写入同样幂等。更换模型、密钥或配置后，旧结果不用于新配置。停用、编辑、删除监控或关闭服务时会取消正在运行的任务；任务最多运行 9 分钟。用户端仅接收状态、时间、耗时与通过率，不接收密钥、上游地址、远端任务 ID、答案或错误响应正文。

迁移 `246_channel_monitor_candy.sql` 随服务启动的标准迁移流程应用。

后端单元测试：`go test -tags unit ./internal/service -run Candy`。SQL 合约测试在独立测试数据库上设置 `LINAI_CANDY_TEST_DSN` 后运行 `go test -tags unit ./internal/repository -run TestCandyRepositoryPostgresContract`；测试使用临时独立 schema，验证并发认领、10 分钟节流、历史上限及旧配置隔离。
