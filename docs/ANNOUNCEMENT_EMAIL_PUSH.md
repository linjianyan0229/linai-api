# 公告邮件推送

用户在“个人资料 → 公告邮件推送”中主动开启或关闭。默认关闭，收件地址为当前账号邮箱。
第三方登录的占位邮箱不能开启，须先在账号资料绑定可接收邮件的邮箱。
推送与余额提醒独立，不使用余额提醒的额外收件地址。

## 推送规则

- 开启后只接收后续新发布、重新发布或标题/正文/受众/生效时间发生变化的有效公告。
- 修改弹窗方式、保存相同内容或单纯更新记录时间，不触发重复推送。
- 定时公告在开始展示后推送；开启发生在定时开始前的用户可以收到。
- 不补发历史公告；关闭后未发送的邮件不再发送，重新开启也不补发旧队列。
- 与站内公告使用相同的余额及订阅可见条件。草稿、归档、已过期和已被新版本替代的公告不推送。

公告内容以转义文本保留换行，最长显示 6000 字符，用户登录网站查看完整公告。
邮件使用系统现有 SMTP 配置，语言遵循用户开启功能时的界面语言。
每次发送前检查当前订阅开关、账号状态、公告版本及展示时间。
已经交给 SMTP 的邮件无法撤回。

## 实现与运维

迁移 `251_announcement_email_push.sql` 增加独立的用户订阅、发布事件和投递表。
数据库触发器将公告修改和发布事件一起提交，事务回滚不会遗留邮件任务。
历史有效公告在迁移时不生成发布事件。

后台每 15 秒处理任务；分批生成收件队列，并发 SMTP 上限为 2。
数据库唯一约束和投递租约防止多实例同时发送同一任务。失败最多重试 3 次，间隔逐次增加。
SMTP 在网络异常时可能已接受邮件但未返回确认，因此不能保证收件端严格只收到一次。
发信失败不会阻止公告发布，失败状态留在 `announcement_email_deliveries` 中供排查。

用户设置接口为认证后的 `GET/PUT /api/v1/user/announcement-email`，只操作当前会话用户。
PUT 请求体为 `{"enabled":true}` 或 `{"enabled":false}`。

`LINAI_ANNOUNCEMENT_TEST_DSN` 指向专用 PostgreSQL 后，可执行：

```sh
go test -tags unit ./internal/repository -run TestAnnouncementEmailPostgresContract
```

测试在独立 schema 内验证发布事务、定时生效、订阅期限、取消、并发去重和重试。
SMTP 测试只使用本地模拟服务器，不向真实收件人发送邮件。
