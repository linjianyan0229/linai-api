# 峰谷时间倍率

v0.3.62 在「分组管理 → 创建 / 编辑」支持多个峰谷时段与北京时间计费。新分组默认关闭此功能。

高峰、低谷分别提供添加按钮，可配置多个每日循环时段及各自倍率，每组最多 48 段。添加时会拆分现有时段；修改任一边界会同步相邻时段，删除后由前一时段接续，保持全天覆盖并避免重叠。支持跨午夜。所有新峰谷计费、预览和用户端展示固定使用 Asia/Shanghai（北京时间 UTC+8），与服务器当前时区独立。区间包含开始时刻、不包含结束时刻。

## 计算规则

未开启充值等级时，直接使用当前时段的最终倍率，替代原固定分组 / 用户专属倍率。例如原分组 0.8×，高峰设置 1.2×，高峰实际为 1.2×。

开启充值等级时，使用「当前充值等级倍率 × 当前时段系数」。例如等级倍率 0.75×、高峰系数 1.2，实际为 0.9×；低谷系数 0.6 时实际为 0.45×。如果存在管理员手工专属倍率，先用专属倍率替代充值等级的基础倍率，再乘时段系数。

时段规则不进入用户倍率缓存，每次按请求定价时刻选择；已有请求定价快照的路径在一次请求内保持一致，批量图片在提交时保存计价快照。充值到账及退款重新计算等级仍遵循原有最长 30 秒缓存规则。

共享分组倍率的图片 / 视频使用峰谷调整后的倍率；独立图片 / 视频倍率仍按各自设置。渠道或模型本身的定价、模型分时系数继续按各自规则计算。利润控制、在途费用估算、API Key 的计费信息接口使用同一份时段计算逻辑。

## 兼容和展示

既有订阅高峰配置继续有效，不会因普通编辑或升级被转换。管理员开启新峰谷配置后，替代原订阅高峰规则；两种时间规则不能同时启用。此处旧订阅规则保留原先的站点时区；新规则固定北京时间。关闭新峰谷配置后，回到分组 / 充值等级 / 用户专属的基础倍率。

用户充值页展示当前实际倍率和多段时间表，模型广场、可用渠道和 API 密钥页面也展示时段规则；页面价格随北京时间的时段边界自动切换。

- 数据：新增 `groups.time_rate_periods`，空数组表示关闭；启用时为 2–48 段。旧两段数据可直接读取。每段可带 `kind: "peak" | "valley"` 作为展示分类，不影响实际倍率计算。
- API：分组创建、更新接受 `time_rate_periods`；更新时省略保留原值，传 `[]` 关闭。
- 缓存：认证快照升级版本，携带时段与充值档位；迁移中的持久化失效触发器覆盖两种配置变更。
- 验证：跨午夜、精确边界、北京时间、直接 / 叠加计算、媒体独立倍率、快照往返、利润预演、上游计费探测、数据库触发器、配置保存和页面边界自动更新。

示例：

```json
{
  "time_rate_periods": [
    { "kind": "peak", "start": "08:00", "end": "12:00", "rate_multiplier": 1.2 },
    { "kind": "valley", "start": "12:00", "end": "18:00", "rate_multiplier": 0.6 },
    { "kind": "peak", "start": "18:00", "end": "22:00", "rate_multiplier": 1.1 },
    { "kind": "valley", "start": "22:00", "end": "08:00", "rate_multiplier": 0.5 }
  ],
  "peak_rate_enabled": false
}
```
